# DaVino — конструктор дегустаций (кейс РСХБ)

Открытые и слепые дегустации вина. Организатор собирает событие с ноутбука, гости оценивают вина с телефона
по QR-коду, итоги публикуются, а валидные оценки уходят в «Народный винный рейтинг».

> **Доступ.** Организатор регистрируется по email и паролю (`/register`, `/login`); его дегустации собраны
> в «Моих дегустациях» на главной. Кабинет дегустации по-прежнему открывается секретной ссылкой
> `/org/[adminKey]` — это резервный вход, так же работает демо. Гости входят по QR без регистрации. Импорт в
> рейтинг пока без авторизации (см. [контракт](docs/rating-contract.md#ограничения-и-планы)).

Стек: Next.js 15 (App Router), TypeScript, Prisma + SQLite, Tailwind, zod, qrcode. Node.js ≥ 20.

## Запуск локально

```bash
cp .env.example .env      # укажите NEXT_PUBLIC_BASE_URL = http://<IP ноутбука>:3000
npm install
npm run dev               # создаёт или обновляет SQLite и запускает dev-сервер на :3000
npm run seed              # демо-данные; идемпотентно, можно запускать сколько угодно
```

- Демо-кабинет: `/org/demo-organizer-public-key`, код для гостей: `DEGUST`. Кнопка
  «Демо: создать дегустацию» (главная и `/login`, отключается через `NEXT_PUBLIC_SHOW_DEMO=false`) входит в общий демо-аккаунт без пароля и открывает форму создания.
  В демо-аккаунте не больше 20 дегустаций, старше 24 часов удаляются при создании новых, создание ограничено 5 в час
  по IP; профиль менять нельзя.
- Народный рейтинг: `/rating`.
- Чтобы гости зашли с телефонов, ноутбук и телефоны должны быть в одной Wi-Fi-сети, а в `NEXT_PUBLIC_BASE_URL`
  должен стоять IP ноутбука. QR-код строится только из этого адреса, `localhost` в него не попадает. Cookie гостя
  ставится и по http (`npm run dev` и `npm start`); флаг `Secure` она получает, только когда сайт открыт по https.

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | Путь к SQLite относительно `prisma/schema.prisma`, например `file:./dev.db` |
| `NEXT_PUBLIC_BASE_URL` | Публичный адрес сайта для QR-кодов и ссылок. Встраивается при сборке |
| `NEXT_PUBLIC_SHOW_DEMO` | Демо включено по умолчанию. `false` — убрать кнопку «Демо: создать дегустацию» (главная и `/login`), блок «Демо» и демо-вход. Встраивается при сборке |
| `SESSION_SECRET` | Подпись cookie сессии организатора. Длинная случайная строка, в production обязательна |
| `EXPORT_SALT` | Соль анонимного `guestHash` при экспорте в рейтинг. Длинная случайная строка, после запуска не менять |

## Как провести дегустацию

0. **Аккаунт** (`/register`, `/login`) — обязателен для создания дегустации. При регистрации: email, пароль, имя
   для гостей («Организатор: …») и согласие на обработку данных ([`/privacy`](app/privacy/page.tsx) —
   страница-заглушка); организация, город и описание — по желанию. ФИО не запрашивается. Подтверждение email и
   восстановление пароля (`/forgot-password`) — в планах, письма не отправляются. В `/profile` — статистика
   (проведённые дегустации, гости, оценки, переданные в рейтинг) и правка публичных данных. Список дегустаций —
   в кабинете `/cabinet`. Удалить дегустацию можно там же или внизу вкладки «Настройки» (с подтверждением; публичную
   демо удалить нельзя). Оценки, уже переданные в рейтинг, остаются. Секретная ссылка `/org/[adminKey]` остаётся
   резервным входом в кабинет конкретной дегустации.
1. **Главная `/`** → «Я организатор» → «Войти» или «Перейти в кабинет» → «Создать дегустацию» (`/cabinet/new`; старый
   `/new` перенаправляет туда): название, режим (открытая или слепая), шкала (100 баллов, 5 звёзд,
   10 баллов), заметки.
2. **Программа** — подобрать вина из каталога или добавить своё и выстроить порядок. Фото бутылки
   загружается и в каталоге, и в программе: оно одно на вино и видно во всех дегустациях с ним (сжимается в
   браузере до 800px, хранится в БД, менять можно и после запуска; в публичном демо-кабинете — нельзя). Без фото
   показывается шаблон: бутылка и бокал в цвет вина. В слепом режиме до раскрытия гость видит бутылку в пакете,
   а фото сервер отдаёт только после раскрытия.
3. **Проведение** — показать гостям QR-код (на весь экран или листком A4 для печати с названием, организатором и
   кодом), нажать «Запустить» и открывать вина по одному. Под каждым вином
   счётчик «проголосовали X из N», он обновляется каждые 5 секунд. Ниже список гостей: удалить гостя или
   отдельную оценку можно с подтверждением, счётчики пересчитаются. «Завершить дегустацию» закрывает приём оценок.
4. **Итоги** — сводка по каждому вину: среднее, число голосов, разброс, балл из 100, место, заметки гостей без
   имён. В слепой дегустации бутылку можно раскрыть («Раскрыть №N»), как только закрыто голосование по ней, а
   «Раскрыть все» становится доступно, когда закрыты все вина. Через 5 секунд гость видит раскрытое вино под своим номером и окно
   «Вы поставили X, среднее Y». Здесь же таблица отброшенных оценок с причиной и блок «Как защищены голоса». Дальше: «Опубликовать итоги» (в слепой дегустации
   только после раскрытия всех бутылок), «Передать в рейтинг» и «Скачать JSON».
5. **Гость** (`/t/[код]`) — входит по QR без регистрации. До ввода имени видит карточку дегустации: название, дату,
   место, «Организатор: имя, организация, город», режим и число вин (в слепой — без названий), «Оценки анонимны,
   имя можно не вводить». Оценивает открытые вина и пишет заметку. После
   публикации видит итоги на `/t/[код]/results`: места, средние баллы и рядом свою оценку.

## Скрипты

| Скрипт | Что делает |
|---|---|
| `dev` | миграции (`prisma/migrate.ts`) + `next dev` |
| `build` | `prisma generate` + `next build` |
| `start` | миграции, seed, `next start` (для Render, где SQLite сбрасывается) |
| `migrate` | `prisma migrate dev`: новая миграция после правки схемы |
| `seed` | идемпотентный seed |
| `typecheck` | `tsc --noEmit` |

## Устройство

- `app/` — страницы и тонкие API-роуты: разобрать вход через zod, вызвать сервис, вернуть JSON.
- `services/` — бизнес-правила: переходы статусов, защита от двойного голоса, раскрытие бутылок, сводка,
  экспорт (`exportService`) и идемпотентный импорт в рейтинг (`ratingService`).
- `lib/session.ts` — сессия организатора: подписанный HMAC токен в httpOnly-cookie; `services/organizerService.ts` —
  регистрация и вход (bcryptjs), `lib/rateLimit.ts` — ограничение неудачных входов организатора и частоты
  запросов гостя (вход и оценка, по IP + коду дегустации, в памяти процесса).
- `lib/dto.ts` — всё, что уходит клиенту. Пока бутылка не раскрыта, гость получает только «Вино №N»: данных
  нераскрытого вина нет ни в API, ни в HTML или RSC-payload, сервер даже не читает их из БД.
- `lib/scales.ts` и `lib/stats.ts` — шкалы, нормализация к 0..100, средние и места. Сводка, итоги гостя и
  рейтинг считаются одними и теми же функциями.
- Формат передачи в рейтинг — [docs/rating-contract.md](docs/rating-contract.md).

## Render

Build: `npm install && npm run build`, Start: `npm start`.
Env: `DATABASE_URL=file:./prod.db`, `NEXT_PUBLIC_BASE_URL=https://<сервис>.onrender.com` (задать до сборки),
`SESSION_SECRET`, `EXPORT_SALT`.
SQLite на Render живёт до перезапуска сервиса: демо-данные восстанавливает seed, остальные дегустации,
аккаунты организаторов и импортированные оценки пропадают.
