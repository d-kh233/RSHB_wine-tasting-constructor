# Конструктор дегустаций — кейс РСХБ

Открытые и слепые дегустации вина. Организатор собирает событие с ноутбука, гости оценивают вина с телефона
по QR-коду, итоги публикуются, а валидные оценки уходят в «Народный винный рейтинг».

> **Авторизация в планах.** Сейчас организатор входит по секретной ссылке `/org/[adminKey]`, которую получает
> при создании дегустации. Другого входа нет, поэтому ссылку нужно сохранить. Импорт в рейтинг тоже пока без
> авторизации (см. [контракт](docs/rating-contract.md#ограничения-и-планы)).

Стек: Next.js 15 (App Router), TypeScript, Prisma + SQLite, Tailwind, zod, qrcode. Node.js ≥ 20.

## Запуск локально

```bash
cp .env.example .env      # укажите NEXT_PUBLIC_BASE_URL = http://<IP ноутбука>:3000
npm install
npm run dev               # создаёт или обновляет SQLite и запускает dev-сервер на :3000
npm run seed              # демо-данные; идемпотентно, можно запускать сколько угодно
```

- Демо-кабинет: `/org/demo-organizer-public-key`, код для гостей: `DEGUST`.
- Народный рейтинг: `/rating`.
- Чтобы гости зашли с телефонов, ноутбук и телефоны должны быть в одной Wi-Fi-сети, а в `NEXT_PUBLIC_BASE_URL`
  должен стоять IP ноутбука. QR-код строится только из этого адреса, `localhost` в него не попадает. Cookie гостя
  ставится и по http (`npm run dev` и `npm start`); флаг `Secure` она получает, только когда сайт открыт по https.

### Переменные окружения

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | Путь к SQLite относительно `prisma/schema.prisma`, например `file:./dev.db` |
| `NEXT_PUBLIC_BASE_URL` | Публичный адрес сайта для QR-кодов и ссылок. Встраивается при сборке |
| `EXPORT_SALT` | Соль анонимного `guestHash` при экспорте в рейтинг. Длинная случайная строка, после запуска не менять |

## Как провести дегустацию

1. **Главная `/`** → «Я организатор» (`/new`) — создать дегустацию: название, режим (открытая или слепая), шкала (100 баллов, 5 звёзд,
   10 баллов), заметки.
2. **Программа** — подобрать вина из каталога или добавить своё и выстроить порядок.
3. **Проведение** — показать гостям QR-код, нажать «Запустить» и открывать вина по одному. Под каждым вином
   счётчик «проголосовали X из N», он обновляется каждые 5 секунд. «Завершить дегустацию» закрывает приём оценок.
4. **Итоги** — сводка по каждому вину: среднее, число голосов, разброс, балл из 100, место, заметки гостей без
   имён. В слепой дегустации здесь же бутылки раскрываются по одной («Раскрыть №N») или все сразу. Раскрытое
   вино гость видит под своим номером в течение 5 секунд. Дальше: «Опубликовать итоги» (в слепой дегустации
   только после раскрытия всех бутылок), «Передать в рейтинг» и «Скачать JSON».
5. **Гость** (`/t/[код]`) — входит по QR без регистрации, оценивает открытые вина и пишет заметку. После
   публикации видит итоги на `/t/[код]/results`: места, средние баллы и рядом свою оценку.

## Скрипты

| Скрипт | Что делает |
|---|---|
| `dev` | `prisma db push` + `next dev` |
| `build` | `prisma generate` + `next build` |
| `start` | `prisma db push`, seed, `next start` (для Render, где SQLite сбрасывается) |
| `seed` | идемпотентный seed |
| `typecheck` | `tsc --noEmit` |

## Устройство

- `app/` — страницы и тонкие API-роуты: разобрать вход через zod, вызвать сервис, вернуть JSON.
- `services/` — бизнес-правила: переходы статусов, защита от двойного голоса, раскрытие бутылок, сводка,
  экспорт (`exportService`) и идемпотентный импорт в рейтинг (`ratingService`).
- `lib/dto.ts` — всё, что уходит клиенту. Пока бутылка не раскрыта, гость получает только «Вино №N»: данных
  нераскрытого вина нет ни в API, ни в HTML или RSC-payload, сервер даже не читает их из БД.
- `lib/scales.ts` и `lib/stats.ts` — шкалы, нормализация к 0..100, средние и места. Сводка, итоги гостя и
  рейтинг считаются одними и теми же функциями.
- Формат передачи в рейтинг — [docs/rating-contract.md](docs/rating-contract.md).

## Render

Build: `npm install && npm run build`, Start: `npm start`.
Env: `DATABASE_URL=file:./prod.db`, `NEXT_PUBLIC_BASE_URL=https://<сервис>.onrender.com` (задать до сборки), `EXPORT_SALT`.
SQLite на Render живёт до перезапуска сервиса: демо-данные восстанавливает seed, остальные дегустации и
импортированные оценки пропадают.
